# 直播场景统一：三个场景预设 + 主播控制指令

**日期**：2026-10-18
**状态**：设计已确认，待实施
**所属规划**：直播功能统筹规划的子项目 2（子项目 1 为语音交互 v2，已合并）

## 问题

直播行为分散在互不相关的开关里：弹幕处理方式（`douyinChatMode`：AI 回复 / 念弹幕）、冷场暖场、冷场自动唱跳、各类答谢欢迎。F9 只能切弹幕处理方式，切到「游戏陪播」后暖场和自动唱歌照常触发，README 只能写「开播前记得自己关」。一个直播场景要手动配好几处，切换场景更是只能停播改配置。

主播语音目前能做表演、传话、聊天，但不能控制直播本身：让她安静、切场景、停掉正在唱的歌都做不到。

## 目标

1. 三个场景预设：**AI 独播 / 游戏陪播 / 搭档主持**。选一个场景，这组行为就自动对上。
2. 直播中途可用 F9 或语音切场景，即时生效。
3. 主播专属语音控制指令：切场景、停止表演、清空弹幕、安静一会儿、恢复。观众弹幕不能触发。
4. 现有开关含义不变，作为总开关；老配置自动迁移，主播现在用的模式原样延续。

## 非目标

- 语音不随场景变化：用不用麦克风只看 `douyinVoiceEnabled`。
- 不做每个场景单独可配的完整配置块（只有三个固定场景，灵活性用不上）。
- 不接设置页 UI（抖音设置 UI 从未接进场景，配置仍通过 settings.json）。
- 安静状态不持久化。

## 场景行为

| 行为 | AI 独播（0） | 游戏陪播（1） | 搭档主持（2） |
|---|---|---|---|
| 普通弹幕 | AI 详细回复并引导观众继续聊 | 带昵称念出来，主播来回 | AI 简短回复，把话头留给主播 |
| 冷场暖场 | 开 | 关 | 开，间隔至少 180 秒 |
| 冷场自动唱跳 | 开 | 关 | 关 |
| 进房欢迎、点赞答谢、整点报时、礼物榜 | 开 | 开 | 开 |
| 礼物答谢与庆祝 | 开 | 开 | 开 |
| 主播语音 | 不受场景影响 | 同左 | 同左 |

每一项都先受对应总开关约束：总开关关闭则任何场景都关闭（如 `douyinIdleChatterEnabled=false` 时三个场景都不暖场）。场景只能在总开关允许的范围内收紧。

## 安静状态

主播说「安静一会儿」进入，默认 `douyinQuietMinutes`（5）分钟后自动恢复，或说「可以说话了」提前恢复。

- **保留**：礼物语音答谢；主播语音的全部响应（指令确认、传话、对话回复）。
- **关闭**：AI 回弹幕、念弹幕、冷场暖场、冷场自动唱跳、观众的点歌/换角色/触发规则、进房欢迎语、点赞答谢语、整点报时、礼物榜；大额礼物的欢呼跳舞与大头特写、触发规则里配置的礼物动作也省掉，只说答谢语。
- **照常记账**：弹幕进观众记忆和聊天上下文，点赞计数，进房记录来访，礼物计入观众画像与礼物榜数据。恢复后 AI 回复仍有上下文，老观众仍认得出。
- 进入安静时，播报队列里已排队的欢迎、点赞答谢、报时等条目丢弃（她当前那句在主播唤醒时已被打断）。
- 自然到期时她说「我回来啦～」。
- 停播、重启程序时退出安静状态。

## 主播控制指令

只来自主播语音（`InjectVoiceChat` 入口），观众弹幕里的同样文字按普通弹幕处理。识别规则同传话开头词：去掉句首标点后只认句首，同时命中取最长；本地匹配，零延迟。

| 指令 | 默认说法 | 效果 | 反馈 |
|---|---|---|---|
| 切场景 | 「切到」「切换到」「换到」+ 场景名；场景名：游戏、陪播 → 游戏陪播；搭档、主持、双人 → 搭档主持；独播、自己播 → AI 独播 | 切换场景并写入配置文件 | 念确认语 |
| 停止表演 | 「别唱了」「别跳了」「停一下」 | 停正在唱的歌（`SongService.StopSong`）和正在跳的舞（`AvatarDancePlayer.StopPlay`，含连跳队列） | 「好～」 |
| 清空弹幕 | 「别念了」「清空弹幕」 | 丢掉播报队列里排队的条目 | 不出声 |
| 安静 | 「安静一会儿」「先别说话」 | 进入安静状态 | 「好，我先安静 N 分钟～」 |
| 恢复 | 「可以说话了」「恢复」 | 提前结束安静 | 「我回来啦～」 |

识别顺序：**控制指令 → 开头词传话 → 唱跳/换角色/聊天（不变）**。控制指令必须最先：「别唱了」若先进弹幕管线，「唱」字会被当成点歌意图。

各指令的说法可在 settings.json 增减。

**F9**：在三个场景间循环切换（独播 → 陪播 → 搭档 → 独播），与语音切场景走同一个函数，同样念确认语。

## 组件

### Core（纯逻辑，EditMode 测试）

**`LiveScene`**：`enum LiveScene { Solo = 0, Game = 1, Duo = 2 }`

**`LiveSceneResolver`**：

- 输入：总开关（AI 回复、欢迎、点赞答谢、礼物、暖场及其间隔、自动唱歌、自动跳舞、直播运营）、当前场景、是否安静。
- 输出 `LiveBehavior`：弹幕处理方式（AI 详细 / AI 简短 / 念弹幕 / 不处理）、暖场开关与间隔、自动唱歌、自动跳舞、观众指令是否响应、礼物庆祝（跳舞特写与触发规则礼物动作）是否执行、礼物语音答谢是否执行、低优先级播报（欢迎/点赞答谢/报时/礼物榜）是否放行。
- 规则见上两节；搭档暖场间隔 = max(总配置间隔, 180)。

**`LiveSceneMigration`**：

- `ResolveScene(int storedScene, int legacyChatMode)`：`storedScene` 缺失（-1）时按 `legacyChatMode` 推导（1 → Game，其余 → Solo）；`storedScene` 越界（不是 0～2）时回退 Solo 并报告需要警告。

**`OperatorCommandParser`**：

- 输入：剥完唤醒词的指令文字、各指令的说法配置。
- 输出：`OperatorCommand`（类型：SwitchScene / StopPerformance / ClearQueue / Quiet / Resume / UnknownScene）及参数（目标场景）。不是控制指令返回 false，交给后续传话与弹幕管线。

### Unity 层

| 组件 | 改动 |
|---|---|
| `DouyinLiveManager` | 持有当前场景与安静状态（到期时间）；`ApplySettings` 及场景/安静变化时调用 `LiveSceneResolver`，把结果下发给 `DanmakuAIService`（Enabled、VerboseChat）、`DanmakuReader`、`IdleChatterService`（Enabled、IdleThreshold、AutoSongEnabled、AutoDanceEnabled）、礼物与观众指令的路由；`InjectVoiceChat` 入口最先识别控制指令；`Update` 处理 F9 与安静到期；`StopLive` 退出安静。`Route` 中：安静时观众弹幕只记账不响应、礼物跳过触发规则直接答谢语 |
| `SpeechPipeline` | 新增「低优先级静音」开关：开启时丢弃新入队的 Welcome / LikeThanks / Milestone 优先级条目，并清掉已排队的这几类；新增清空队列供「清空弹幕」用（已有 `ClearQueue`） |
| `RewardService` | 新增只说答谢语、不跳舞不特写的礼物处理入口，供安静期间使用 |
| `SaveLoadHandler` | 新增 `douyinScene`（默认 -1 表示待迁移）、`douyinQuietMinutes`（5）、各指令说法列表；`douyinChatMode` 标为废弃 |

主播指令的确认语一律用 `AIReply` 优先级入队（安静期间低优先级静音不会吞掉它）。原 F9 确认语用的 `Milestone` 改为 `AIReply`。

## 配置

```jsonc
"douyinScene": 0,                 // 0=AI独播 1=游戏陪播 2=搭档主持；缺失时从 douyinChatMode 迁移
"douyinQuietMinutes": 5.0,        // 「安静一会儿」的时长
"douyinCmdSwitchPrefixes": ["切到", "切换到", "换到"],
"douyinCmdSceneGame": ["游戏", "陪播"],
"douyinCmdSceneDuo": ["搭档", "主持", "双人"],
"douyinCmdSceneSolo": ["独播", "自己播"],
"douyinCmdStop": ["别唱了", "别跳了", "停一下"],
"douyinCmdClearQueue": ["别念了", "清空弹幕"],
"douyinCmdQuiet": ["安静一会儿", "先别说话"],
"douyinCmdResume": ["可以说话了", "恢复"],
// douyinChatMode 已废弃，只在 douyinScene 缺失时读取一次用于迁移
```

## 出错处理

| 情况 | 处理 |
|---|---|
| `douyinScene` 越界 | 按 AI 独播，日志警告 |
| 切场景时场景名识别不出 | 不切换，她说「没有这个模式哦，可以说游戏陪播、搭档主持或独播」 |
| 切到当前场景 | 不重复切换，她说「已经是 XX 模式啦」 |
| 安静中再说「安静一会儿」 | 重新计时 |
| 没在安静时说「可以说话了」 | 忽略，不出声 |
| 没在唱跳时说「别唱了」 | 忽略，不出声 |
| 安静中切场景 | 场景照切，安静保持，确认语照常说 |
| 停播 | 退出安静 |

## 测试

1. **`LiveSceneResolver`**：场景表每一格；总开关关闭时三个场景都关闭；搭档暖场间隔 max 规则；安静状态只剩礼物语音答谢与主播响应。
2. **`OperatorCommandParser`**：每种指令；场景名各种说法；只认句首；同时命中取最长；识别不出的场景名返回 UnknownScene；空输入；自定义说法；非指令返回 false。
3. **`LiveSceneMigration`**：缺失时从 `douyinChatMode` 推导（0/1/其他）；越界回退并要求警告。
4. **编译 + 全量回归**：现有 233 个测试保持通过。
5. **真机验收**（主播）：F9 循环三场景且念确认语；陪播放置 6 分钟不暖场不自动唱；搭档时弹幕回复变短；语音切场景（含识别不出、切到当前场景）；「安静一会儿」后发弹幕、点赞、点歌、进房都没反应，送大礼物只道谢不跳舞，到期说「我回来啦」；「可以说话了」提前恢复；「别唱了」停歌、「别跳了」停舞；「别念了」清空积压弹幕；老配置（只有 `douyinChatMode: 1`）启动后是游戏陪播。
